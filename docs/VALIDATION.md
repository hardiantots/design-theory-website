## Deployment and environment

`next.config.mjs` uses `output: 'export'` and `trailingSlash: true`; route parameters are generated at build time. `vercel.json` uses the Next.js preset, `npm run build` and output directory `out`. There is no runtime API/database/authentication service. Vercel publishing remains deferred at the user's explicit request to continue locally. Framework cache defaults are preserved.

Configuration follows installed Next.js documentation and the official [static export guide](https://nextjs.org/docs/app/guides/static-exports), [Vercel build configuration](https://vercel.com/docs/builds/configure-a-build) and [Vercel ignore guide](https://vercel.com/docs/deployments/vercel-ignore).

The workspace shares installed dependencies with the reference project through an ignored junction; the tracked lockfile supports independent `npm ci`. The Windows native SWC binary does not load, so Next uses its installed WASM fallback and successfully completes the Webpack build. `scripts/finalize-export.mjs` normalizes Windows nested segment filenames into the dot-separated names requested by the router; correctly generated Linux output is unchanged.

## Limits

Real-device WebGL, native macOS/iOS Safari, screen-reader behavior and Vercel cloud deployment remain untested. WebKit and mobile emulation do not prove physical-device behavior. A prior diagnostic observed WebKit access-control messages when a resize was immediately followed by hard navigation while prefetch work was scheduled; this edge case is not claimed as fixed. Current responsive checks use independent viewport contexts.
